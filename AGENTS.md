# Purpose

This file defines the immutable DNA and global architectural governance of the Poké Vicio project. Every AI agent interacting with this repository MUST adhere to these rules.

Poké Vicio is a hybrid retro-modern web video game built with Vue 3, Pinia, GSAP, and Pokémon Showdown engine (`@pkmn/sim`) logic.

## Ownership

Poké Vicio Core Architecture & Development Team.

## Local Contracts

- **Dependency Immutability Mandate & Categorical Prohibition on Mutating `node_modules/` (`Dependency Immutability Mandate`)**: Developers and AI agents are STRICTLY AND CATEGORICALLY PROHIBITED from modifying, editing, patching, or creating files inside `node_modules/` under ANY circumstances. Third-party dependencies and framework packages are immutable runtime artifacts installed via package managers. Copying, transferring, or pasting build artifacts (`dist/`), packages, or files directly into another project's `node_modules/` to test changes is STRICTLY AND CATEGORICALLY PROHIBITED. If a bug or false positive is suspected in `@francogp/auditor` or any installed dependency, the AI agent MUST HALT and report the issue to the human programmer to fix it in the upstream source repository rather than hot-patching `node_modules/`. All cross-project verification MUST execute non-destructively through the canonical remote CLI flag (`project=<path>`) from the auditor workspace or by upgrading via the canonical package update tool (`npm run auditor:update`), NEVER by tampering with `node_modules/`. Mutating `node_modules/` introduces untracked volatile state that is immediately destroyed on the next `npm install`, masks upstream architectural debt, and constitutes a critical operational violation.
- **Universal Architecture Governance & Mandatory Work Planning Alignment Mandate (`/architecture`)**: The `/architecture` governance framework governs all design, structure, runtime behavior, and refactoring across this repository and MUST remain continuously active and strictly enforced. Whenever creating, proposing, or executing any work plan, technical design, refactoring roadmap, or task breakdown (e.g. `/plan`, `/brainstorming`, brain task plans), the proposed work MUST strictly align with and satisfy `/architecture` and its complete contents: the 6 Mandatory Design Pillars (`/domain-type-first`, `/clean-code`, `/dox-navigator`, `/ponytail`, `/auditor`, `/fallow`), the Primary Debugging Guide (`/systematic-debugging` - RED-GREEN First Mandate), decoupled layering, Node.js 26+ native standard library mandate, dynamic SSoT configuration, and official framework tools priority. Deviating from `/architecture` or executing plans that bypass its pillars is strictly prohibited.
- **Mandatory Official Tools Priority & Prohibition on Premature Ad-Hoc Scripts**: Developers and AI agents MUST ALWAYS prioritize and use the official CLI tools provided by the framework and package scripts (`npm run auditor:findings`, `npm run auditor:rules`, `npm run auditor:by-rule`, `npm run auditor:by-file`, `npm run auditor:dupes`, `npm run auditor:magic`, `npm run auditor:motion`, `npm run auditor:o1`, `npm run auditor:dependencies`, `npm run auditor:version`, `auditor guide <ruleId>`, `vp check`) before attempting manual inspection or writing code. Reinventing the wheel by creating scratch scripts or ad-hoc `node -e` one-liners for tasks already covered by official tools is STRICTLY PROHIBITED. Creating temporary scripts in `scratch/` is permitted ONLY as an exceptional last resort when no official tool exists for the specific diagnostic or verification task. When invoking npm scripts with flags or subcommands, always use `--` (e.g. `npm run auditor:motion -- --help`, `npm run auditor -- guide <ruleId>`) or invoke the installed binary directly, NEVER invoke `npx`.
- **Absolute Prohibition on Unrequested Destructive Git Commands**: AI agents are STRICTLY AND CATEGORICALLY PROHIBITED from executing destructive Git commands (`git reset --hard`, `git checkout --`, `git clean`, `git restore`, `git push --force`) that discard or overwrite working tree changes or commit history without explicit prior authorization from the human programmer.
- **AI Agent Chat Communication & Interactive Language Mandate**: The AI assistant / agent MUST strictly consult `.auditor/audit.config.ts` and communicate, converse, respond, and chat with the user in Spanish (`'es'`). This conversational chat language is explicitly separate and distinct from the repository file writing and documentation language (`config.documentation.language`), which strictly governs code comments, commit messages, documentation, markdown files, and codebase artifacts. The AI agent must dynamically consult these configurations and never confuse or conflate the chat language with the file writing language.

### 0. Senior Developer Mindset, Core Engineering & Domain Contracts

You are a lazy senior developer (efficient, never careless): (1) YAGNI, (2) standard library, (3) native platform feature, (4) installed dependency, (5) one line, (6) minimum working code. Never compromise on input validation, data-loss prevention, security, accessibility, or explicit user requirements.

- **Zero Error Suppression, Zero-Fallback Config & Error Cause**: Never swallow errors via empty catch blocks or mock fallbacks (`servers.local.json` derives strictly from `.env`/secrets, never `servers.defaults.json`). Declare uninitialized domain variables (`let x: DomainId;`, never `'' as DomainId`) for TS2454 exhaustiveness, and re-throw with `new Error(..., { cause: err })`.
- **Database Parity, Immutable Migrations & Zero Auto-Heal**: SQLite and PostgreSQL must behave 100% identically (`describeWithDatabase`). Code in `src/` must never auto-heal, translate Spanish-to-English IDs, or synthesize missing properties at runtime. All schema evolutions and backfills run via static forward-only migrations in `database/migrations/` (`.sql` + `.sqlite.sql`); committed migrations are **STRICTLY IMMUTABLE** (`_migrations` ledger). All migration runners (`sqliteEngine.ts`, `update_supabase_db.ts`, `postgres_test_container.ts`, `upgrade_backup.ts`, `diagnose_account.ts`) enforce atomic `ON_ERROR_STOP` fail-fast rollback.
- **1:1 Entity Serialization & 2-Tier Persistence (`SaveCoordinator`)**: Core entities (`Pokemon`, `SaveData`, `PokemonEgg`) use exclusively `saveSerializer.ts` (`serializePokemonTeam`, `deserializePokemonTeam`, `withPersistedPokemonGender`); subset types (`*SnapshotEntry`, `*PartialData`) in `passive_teams`, `market_listings`, `trade_offers`, `daycare_slots`, or `war_defenders` are forbidden. `SaveCoordinator` enforces Tier 1 local debounce (1.5s) and Tier 2 remote throttle (60s), using `forceRemote: true` only on critical transactions (GTS, PvP settlement, `claimAsset`, `beforeunload`).
- **3-Tier Bug Fixing, Dual Gatekeepers (`auditor` + `test`) & Real Engine Parity**: Both `npm run auditor` and `npm run test` are mandatory (every sub-auditor in `scripts/auditors/` requires a test in `tests/node/auditors/`). Never inflate `testTimeout`. Bug fixes require: (1) **Tier 1** isolated unit test failing in RED before editing `src/` (`describeWithDatabase` for DB), (2) **Tier 2** integration test against real `@pkmn/sim`, `showdownWorkerClient.ts`, `showdownBridge.ts`, `turnActionResolver.ts`, and `DBRouter` (mocking core subsystems under test is forbidden), and (3) **Tier 3** Playwright E2E simulation via `/game-simulation` (passive joystick, `#id` locators, 10s timeout, zero timers, dual-driver persistence).
- **O(1) Lookups, Reactive Cloning & Temporal API**: Use `Record<DomainId, T>`, `ReadonlySet<DomainId>`, or `Map<DomainId, T>` instead of hot-path `.find()`/`.filter()`/`.includes()`. `JSON.parse(JSON.stringify(...))` is forbidden (`o1-json-clone`): use `structuredClone(obj)` for plain objects and `cloneReactive(obj)` (`@/logic/utils/cloneUtils.ts`) for Vue/Pinia proxies. Legacy `Date.now()` and `new Date()` are forbidden: use `performance.now()` for durations and `Temporal.Now.instant()` for timestamps.
- **Zero Suppressions, No Passthrough Aliases, Cache Isolation & Dead Code**: Bypass directives (`fallow-ignore*`, `eslint-disable`, `oxlint-disable`, `@ts-nocheck`, `@ts-ignore`, `// *-ok`) and passthrough aliases (`export type Foo = Bar;`) are forbidden. Use `readonly` / `as const` named constants. Isolate `"tsBuildInfoFile"` in `.tsbuildinfo/`. Security (CWE) uses exclusively `fallow security`. For unused files/exports, never use blanket globs in `.fallowrc.json`: wire active components, delete genuine dead code and update DOX, or consult the user before adding `ignoreExports` for dynamic/domain-tuple exports.
- **Canonical Battle Engine, Worker Decoupling, Assets (`getAssetUrl`) & `useUpdateStore`**:
  1. **Single Combat Pipeline**: All battle modes (PvE, Gym, War, PvP, Spectator, Replay) run through `executeCanonicalTurn` and shared arena components (`BattleArena.vue`, `BattleArenaControls.vue`, `BattleActionButtons.vue`, `BattleQuickTeam.vue`, `PokemonSelectionModal.vue`) via `BaseBattleSession` subclasses and `BattleUiConfig`.
  2. **Web Worker Showdown Boundary (`validate_client_sim_decoupling.ts`)**: Main-thread `src/` files must never import runtime values from `@pkmn/sim` or `@pkmn/randoms` (`import type` only); all simulation/team generation runs in `showdown.worker.ts` or backend runners.
  3. **Centralized Assets & Artwork (`getAssetUrl`)**: Resolve all assets via `getAssetUrl(ASSET_TYPES.<CATEGORY>, id, options)` from `@/logic/services/assetService` (no hardcoded `/assets/...` or `/sprites/...` paths). Artwork must strictly depict `ENABLED_POKEMON_IDS`, use Spanish-only pixel text, and omit burned-in dates/years ([event_system_manual.md](.agents/skills/project-standards/references/systems/event_system_manual.md)).
  4. **Update Store (`/login`)**: Version checks and chunk recovery run exclusively via `useUpdateStore` (`src/stores/update.ts`), terminating workers, calling `authStore.logout(true, true)` (Save Shield), setting `block_autologin`, and reloading to `/login`.
