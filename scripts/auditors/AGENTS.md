# Purpose

Domain module for all static, runtime, domain, database, FSM, and asset auditors in the Poké Vicio project.

## Ownership

Tooling / Quality Engineers.

## Directory Navigation Index

- [scripts/auditors/architecture/AGENTS.md](./architecture/AGENTS.md): AST rules, Fallow intelligence, Z-index sync, CSS checker, constant duplicates.
- [scripts/auditors/assets/AGENTS.md](./assets/AGENTS.md): Pokemon sprites coverage, item sprite collisions.
- [scripts/auditors/documentation/AGENTS.md](./documentation/AGENTS.md): Relative links and DOX hierarchy integrity.
- [scripts/auditors/domain_data/AGENTS.md](./domain_data/AGENTS.md): Domain types integrity, Pokemon DB, moves, abilities, items, translations, Spanish IDs, tooltip mechanics.
- [scripts/auditors/fsm/AGENTS.md](./fsm/AGENTS.md): Mermaid diagrams parity, FSM implementation, flow parity, transition coverage.
- [scripts/auditors/persistence/AGENTS.md](./persistence/AGENTS.md): SQLite in-memory migrations, save schema migrations, backup fixtures.

## Local Contracts

- **Mandatory OOP Inheritance Mandate**: Every sub-auditor in this directory MUST inherit from either `BaseAuditor<TRuleId>` or `FileScanAuditor<TRuleId>` from `scripts/lib/auditorBase.ts`. Creating standalone procedural scripts, custom directory walkers (`fs.readdir` loops, `getAllFiles`, `walkSourceFiles`, `walkFiles`, `walkDir`, `collectMarkdownFiles`), or ad-hoc result printers is strictly forbidden.
- **Single Source of Truth Directory Ignore Mandate (`CANONICAL_IGNORE_DIRS`)**: Sub-auditors in this directory MUST NEVER declare local ignore sets (`const IGNORE_DIRS`, `const SKIP_DIRS`, `const SKIP_NAMES`, `const SKIP_SUBDIRECTORIES`) or ad-hoc recursive file walkers (`walkFiles`, `walkDir`, `collectMarkdownFiles`). All directory ignores MUST be sourced strictly from `CANONICAL_IGNORE_DIRS` in `scripts/lib/auditorBase.ts` (layered via `ALWAYS_IGNORE_DIRS` and `CODE_ONLY_IGNORE_DIRS`). Additional ignore patterns must be provided via `extraIgnorePatterns` in constructor options, and documentation auditors requiring access to documentation trees (`docs/`, `.agents/`) must declare `unignoreDirs: ['docs', '.agents']`.
- **Universal Scratch Isolation & Ephemeral Asset Mandate**: All temporary databases, test simulation exports, reports, and local backup imports MUST reside strictly inside `scratch/` (e.g. `scratch/database/clean_template.db`, `scratch/reports/`, `scratch/audits/`). Source code directories (`src/`, `database/`, `scripts/`, `tests/`, `supabase/`) MUST NEVER contain temporary directories (`temp/`, `tmp/`, `temp_*`, `ephemeral/`) or temporary files. Adding `.gitignore` entries to ignore temporary files inside source trees is strictly prohibited. Enforced continuously by `validate_ephemeral_storage_isolation.ts`.
- **Auditor Test Environment Isolation Mandate (`projectRoot`)**: Sub-auditors accepting custom directory roots or root paths for testing MUST forward `projectRoot` into `super({...})` (`AuditorOptions.projectRoot`), ensuring unit tests executing within temporary sandbox directories (`tempDir`) never accidentally scan the live repository.
- **Shared AST Engine & Zero Duplicate Parse Mandate**: Sub-auditors performing TypeScript AST analysis MUST declare `requiresAst: true` and consume `SharedAstContext` (or receive `sourceFile` automatically in `FileScanAuditor.scanFile(relPath, content, sourceFile)`). Calling `ts.createProgram`, `ts.createSourceFile`, or parsing TypeScript ASTs independently in isolated loops is strictly forbidden. All AST parsing is centralized, cached, and preheated by the orchestrator (`audit_full.ts`) and `SharedAstContext`.
- **Dynamic Auto-Discovery Policy (Zero Hardcoding)**: The master audit orchestrator (`scripts/maintenance/audit_full.ts` via `scripts/maintenance/auditScanner.ts`) scans this directory recursively. Every `.ts` auditor file is automatically discovered and incorporated into the general audit run. Hardcoding lists or arrays of sub-auditors is strictly forbidden.
- **Universal Audit Behavior (Console Summary + JSON in Scratch)**: Every auditor in this directory executes under a single, universal standard:
  1. **Console (`stdout`)**: ALWAYS outputs formatted step-by-step progress lines followed by the clean human visual summary table (Box-Drawing borders, standardized badges `[ ✅ PASS ]`, `[ ❌ FAIL ]`, `[ ⚠️ WARN ]`, aligned duration, domain metrics, and error/warning counts).
  2. **Disk (`scratch/audits/`)**: ALWAYS writes the 100% complete structured JSON conforming to `StandardAuditResult` to `scratch/audits/<family>/<id>.json` (and `scratch/audits/latest_audit.json` for global runs). AI agents needing line-level details must read `scratch/audits/latest_audit.json` directly from disk.
- **Superclass Table Rendering & 80-Column Terminal Boundary Mandate**: All terminal output tables generated by sub-auditors and report scripts (`report_fallow.ts`, `report_complexity.ts`, `report_audit_findings.ts`, `audit_full.ts`) MUST be rendered through the centralized `renderBoxTable<T>` from `scripts/lib/unifiedTheme.ts`. Tables MUST NOT exceed 80 columns in width, MUST prevent line wrapping across platforms, and MUST calculate cell and padding widths using `getVisualWidth` to account for multi-byte Unicode and double-width emojis (`✅`, `❌`, `⚠️`).
- **Strict Finding Deduplication & High-Signal Reporting Mandate**: Terminal summary tables and reporting CLI scripts (`report_audit_findings.ts`, `renderBoxTable` in `scripts/lib/unifiedTheme.ts`) MUST group and deduplicate findings sharing identical file path, line number, and rule violation before rendering. Repeating identical warning or error rows clutters developer terminal output, wastes token budget in AI workflows, and diminishes reporting signal quality.
- **Progress Stream Cleanliness Mandate**: The master streaming execution tree (`audit_full.ts`) MUST remain 100% clean and concise during task completion. Intermediate findings, suggestions, and warnings MUST NOT be dumped in-line inside the progress stream (`│ ✖ ...`); all errors and warnings must be consolidated exclusively in the final Box-Drawing summary table and bottom error sampling.
- **Official NPM Scripts Execution Mandate**: All developer verification, linting, and audit tasks MUST be invoked through official scripts defined in `package.json` (such as `npm run lint`, `npm run audit`, `npm run audit:findings`). Ad-hoc executions (`node -e "..."`, direct unflagged node calls) are strictly prohibited.
- **Direct Execution Guard Mandate**: CLI entrypoints MUST be guarded with `if (process.argv[1] && import.meta.filename && path.basename(process.argv[1]) === path.basename(import.meta.filename)) { await BaseAuditor.runCli(new MyAuditor()); }` so tests can import classes without triggering CLI side effects.
- **Family Subfolder Convention**: Auditors MUST be organized by domain family subfolders:
  - `architecture/`: AST rules, Fallow intelligence, Z-index sync, CSS checker, constant duplicates.
  - `domain_data/`: Domain types integrity, Pokemon DB, moves, abilities, items, translations, Spanish IDs, tooltip mechanics.
  - `persistence/`: SQLite in-memory migrations, save schema migrations, backup fixtures.
  - `fsm/`: Mermaid diagrams parity, FSM implementation, flow parity, transition coverage.
  - `assets/`: Pokemon sprites coverage, item sprite collisions.
  - `documentation/`: Relative links and DOX hierarchy integrity.

## Work Guidance

- Refer to the dedicated skill [auditor-framework](../../.agents/skills/auditor-framework/SKILL.md) for detailed implementation patterns, architectural standards, and bundled templates.
- Subclass `FileScanAuditor` for line-by-line file scanners and `BaseAuditor` for multi-source/composite audits.
- Always declare descriptive metrics (`context.setMetric()`) and structured findings via `this.addViolation()`.
- Keep sub-auditors fast and deterministic.

## Verification

- Run `npm run audit` to verify all auditors execute with unified table styling and generate reports in `scratch/audits/`.
- Run `npm run test tests/node/auditors/` for unit test verification.
