## 1. Fuzzer Subsystem Directory Structure & Taxonomy

The Capa 0 fuzzer operates in pure Node.js and uses `@pkmn/sim` (Pokémon Showdown) directly as its ground-truth oracle:

```

│   └── fuzzer_runner.ts              <- Native fuzzer runner (decoupled from Vitest)
├── generators/
│   ├── fuzzer_team_generator.ts      <- Generates legal, objective-focused test teams
```

## 2. Fuzzer -> E2E Dependency Chain & Oracle Contract

```
run_moves_fuzzer.ts / run_abilities_fuzzer.ts / run_items_fuzzer.ts
  │
  ├── Deterministically simulates battles using @pkmn/sim
  ├── Applies Infinite Punching Bag (IPB) during active item testing
  └── Embeds comprehensive metadata into turn history on disk
        │
        ▼
scripts/e2e/results/fuzzer_certified_cases.json
  │
  ├── section "battle"    ──► Consumed by battle_fsm_sync.simulation.ts
  ├── section "items"     ──► Consumed by battle_held_items.simulation.ts
  └── section "scenarios" ──► Consumed by battle_manual_scenarios.simulation.ts
```

### The Oracle Axiom
- Pokémon Showdown (`@pkmn/sim`) is the **authoritative engine**.
- If Poké Vicio's runtime behavior in `src/` diverges from Showdown's output, **`src/` is wrong**. The simulation is right.
- The Playwright browser test does NOT make combat decisions; it replays the certified choices and history flags generated by the fuzzer.

## 3. Infinite Punching Bag (IPB) Lifecycle Law

### Objective-Scoped Lifecycle
Fuzzer combat execution operates in two distinct, mandatory sequential phases:
1. **Phase 1 (Cheat-Assisted Testing)**:
   - While there are untested moves, items, or abilities remaining in the batch (`hasUntestedItemsAfterTurn === true`), apply Infinite Punching Bag (IPB) healing cheats whenever HP drops below 30% of max.
   - Restorations are saved directly as boolean flags (`p1Heal: true`, `p2Heal: true`, `p1PreHeal: true`, `p2PreHeal: true`) inside each turn's history entry (`history`), linked to `battleTurn`.
   - Both the fuzzer and the Playwright browser replayer read these history flags to apply identical deterministic healing without desync.
2. **Phase 2 (Natural Unassisted Combat Completion)**:
   - As soon as all moves/abilities/items in the batch have been certified (`hasUntestedItemsAfterTurn === false`), IPB cheats **MUST BE IMMEDIATELY DEACTIVATED** (`ipbActive = false`).
   - Combat continues executing naturally turn-by-turn until it ends organically (`simBattle.ended === true`).

### Prohibition on Permanent Cheat Loops
- It is **STRICTLY FORBIDDEN** to keep IPB cheats active indefinitely until max turn limits.
- Keeping IPB cheats active post-testing prevents PP depletion, blocks natural `Struggle` recoil execution, and creates artificial 1000-turn stall loops.
- Battles must always complete naturally to generate a clean, un-truncated choice stream for Playwright E2E replays. Artificial early returns or synthetic battle truncations are strictly prohibited.

## 4. Objective-Driven Cooperative Fuzzer Heuristics

When certifying a move, ability, item, status cure, or switch interaction, every scripted seat MUST prioritize **legal actions that exercise that exact objective** as quickly as possible. The fuzzer is an active coverage instrument, not a passive random battle.

### Heuristic Priority Rules
1. **Targeted Interaction**:
   - If testing a poison-curing berry (*Pecha Berry*), the opposing seat prioritizes a legal poison-inflicting move (e.g. *Toxic* or *Poison Powder*).
   - If testing a type-resistance berry (*Occa Berry*) or type-boost item (*Charcoal*), the opposing or active seat prioritizes a move matching that type (*Flamethrower*).
   - If testing a stat-boost ability (*Intimidate*, *Moxie*), setups force relevant switches or knockouts.
2. **Strict Request Conformance**:
   - Heuristics shape generated team choices and AI priorities, but they MUST NEVER:
     - Inject synthetic outcomes.
     - Mutate an already submitted choice.
     - Bypass Showdown's `|request|` payload.
     - Select an illegal move or switch slot.
     - Replace or rewrite the certified history.
3. **Deterministic Heuristics vs. Real AI**:
   - The fuzzer uses its direct deterministic heuristic agent (`fuzzer_agent.ts`), NEVER the full combat AI (`src/logic/battle/ai/`).
   - The heuristic agent selects only legal objective-triggering choices through the standard Showdown request path.
4. **Observable Evidence Required for PASS**:
   - A case is certified as `PASS` only when observable Showdown protocol evidence occurs (e.g. protocol effect token, damage differential, or status clearance). Merely equipping an item or possessing an ability does not constitute test coverage.

## 5. Worker-Scoped Page Pool & 7-Pillar Atomic Reset Architecture

### Context & Problem Solved
High-volume simulation suites (such as `battle_held_items.simulation.ts` with 50+ batches or `battle_fsm_sync.simulation.ts`) would incur massive cumulative boot overhead (20s+ per test) if restarting the browser and reloading the full Vue bundle for every single case. To achieve 100% fidelity without thread starvation, these suites leverage **worker-scoped browser context reuse** (`WorkerSessionPool`).

### The 7-Pillar Low-Level Reset Protocol (`sim.resetToCleanState()`)
Between batches, the harness executes `resetToCleanState()` to enforce zero cross-batch contamination:

1. **Showdown Worker Purge**:
   - Worker instance terminated and nullified via `testResetShowdownWorker()`.
2. **GSAP Timeline Purge**:
   - All active tweens killed: `gsap.killTweensOf('*')`.
   - Global timeline cleared: `gsap.globalTimeline.clear()`.
   - Timeline timeScale verified at `100`.
3. **Pinia Stores Deep Reset**:
   - `battleStore`: State reset to null, FSM reset to `CONTEXT_SETUP`, stat stages reset to 0.
   - `gameStore`: Active team reset to `[]`, inventory reset to `{}`, notifications history purged.
4. **DOM & Component Hygiene**:
   - Floating toasts, tooltip overlays, and lingering modals removed from DOM.
   - Double `requestAnimationFrame` settling pass to ensure Vue component unmount cycles complete.
5. **PRNG & Deterministic State Reset**:
   - Seed reset to base: `seedVal = 12345`.
   - Scripted choice indices and action stream cursors cleared.
6. **E2E Promise Clearance**:
   - Window-level event promise delegates (`window.__E2E_RESOLVERS__`) cleared to prevent cross-test promise resolution.
7. **Persistence Partition Cleanup**:
   - Database save rows deleted for the dedicated worker user account (`Worker_${workerIndex}`).

### Selective Scope Mandate
Worker-scoped page reuse is **strictly limited to high-density combat suites**. Applying page reuse to:
- Cold-start lifecycle tests (`loading_gate_and_reload.simulation.ts`, `save_shield_restrictions.simulation.ts`),
- Multi-user / multi-tab suites (`gts_transactions.simulation.ts`, `magikarp_contest_multiusers.simulation.ts`), or
- Short domain suites (1–6 tests per file)

is **STRICTLY PROHIBITED**. Cold-boot isolation is essential to prevent WebGL/RAM memory leaks across the 58+ sequential simulation suites and to guarantee genuine first-paint boot fidelity.

### Fail-Fast Guarantee
Page pooling is permitted **ONLY while tests succeed**. If any batch fails:
1. The browser context is destroyed immediately.
2. Failure logs, DOM snapshots, and traces are flushed to disk.
3. The suite halts under the Fail-Fast mandate (`maxFailures: 1`).
